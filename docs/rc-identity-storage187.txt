Correction
client_patch/transport/rc_setup.py now checks identity directories,identity files
and setup lock storage with lstat. It refuses nonordinary files/directories,
Windows reparse points,symlinks and multiply linked identity/lock files. Missing
storage is distinguished from a dangling link. It never repairs or deletes an
unsupported path or changes permissions. Normal existing identities keep their
exact bytes and schema. A directory/lock is checked before opening the lock.

First identity publication is now exclusive:Windows rename,or POSIX hard-link
publication followed by owned temporary cleanup. If another file appears before
publication,it is preserved and validated. A valid identity wins;damaged data
refuses without replacement. Serialization,flush/fsync and cooperative setup
locking remain. This is not immunity to arbitrary malicious same-user filesystem
replacement between metadata checks and open,or a new cross-account ACL policy.
