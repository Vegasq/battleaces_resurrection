Required behavior
Use the existing public1v1 Play button and native matchmaking notification.
The button displays localized Searching... and becomes non-interactable.
A nonmodal top-center panel shows the selected mode, elapsed seconds and its
original Cancel button. Found/cancel/failure dismiss that panel and stop timers.

should use the same supported native flow; Try Deck retains its separate mode.
One ordinary Start Client entry point must expose all of these paths.

Original native contract
MatchmakingButtonVM.OnMapSelected RVA3d23220 invokes Front.JoinMatchmakingQueue
3e3c0d0. After asynchronous MapMeta loading, closure3e4a510 sets local queue
state/mode, snapshots queue-entry DateTime, sends the original request, increments
pending requests and calls UpdateMatchmakingStatus3e35cd0. Thus the old indication
precedes server acknowledgement but follows map preload. Our immediate-feedback
requirement starts that same presentation when the community queue ticket is
accepted, before long preparation. This timing improvement is separate from
reproducing the original appearance.

Front's effective state uses pending requests to select optimistic local state
or confirmed server state. Relevant exact-build fields:
 confirmed queue+128; pending requests+140; local mode+148/local queue+14c;
 confirmed mode+150; queue-entry DateTime+158; matchmaking status+188;
 MatchmakingStateChange event+1e8; selected matchmaking game+138.
UpdateMatchmakingStatus updates both the event-observed button model and routed
MatchmakingStatusSignal. Reconcile all optimistic/confirmed fields under the
current queue generation; setting just one VM flag or posting one signal is
incomplete. Keep existing original-transport/Steam/analytics suppression when
using native presentation; do not restore the retired request path.

Status InQueue5 opens the pooled MatchmakingStatusPanel through
MatchmakingNotification.OnMatchmakingSignal3d59650. None0,LeavingQueue6,

Exact original bindings
PlayMainScreen/MiddleContent/GameButtons/1v1Button binds IsMatching to the
QueueSearchingText child's active state and Interactable to UIButton.
PlayMain.Searching localization key370201198592 resolves to Searching... in
the installed English assets. Ordinary public1v1 must keep the proving-grounds
fake-practice flag false; native button matching otherwise changes behavior.
MatchmakingStatusPanel binds CurrentSecondsInQueue to PlayMain.TimeElapsed
key466271731712. The existing localization uses bold white integer seconds;
retain its font/color/localization instead of inventing mm:ss or an estimate.
OnMatchmakingTimerUpdate3d59d00 derives elapsed time from the stored DateTime;
UINotificationTimer initializes immediately and updates once a second. Keep one
entry timestamp and a consistent front clock. This elapsed display is distinct
from the replacement server's30-second AI-fallback deadline.

MatchmakingStatusPanelVM.OnCancelClicked3d25bf0 invokes
Front.LeaveMatchmakingQueue(true)3e3e760. The original method immediately clears
optimistic queue state then sends leave. The replacement must retire the matching
generation, dismiss native search state and reject any later start for that
generation. The disabled Play button is not the supported Cancel target.

ProcessMatchmakingGameFound3e38f70 posts JoiningGameSignal and updates found
state. RGameJoiningGameState then posts ShowLoadingScreenSignal. Original assets
contain Loading . . . and Waiting for Players ... presentation. A Match Found!
localization entry exists, but this bounded trace does not establish a displayed
toast/animation; do not invent one from a string alone.
