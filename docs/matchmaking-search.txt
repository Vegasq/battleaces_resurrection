Current integration
match_search.cpp owns one monotonic presentation ticket. It publishes the native
front state once per transition, allowing the original event observers, pooled
panel and one-second timer to work. It rejects overlapping invite/pending-request
ownership and requires the existing Steam initialization suppression. Clearing
search preserves the last local mode and resets confirmed mode to0. It does not
invoke the original networked Join/Found/Leave handlers.

The existing LeaveMatchmakingQueue hook now routes local public Cancel into that
owner. The callback only records intent; a later Unity update dismisses the
panel. A pending original map builder retains its roots/world lease until its
callback is discarded, so another search cannot reuse that native builder while
it is still completing. A pooled panel address is not a generation identifier.
Late found/release calls for a retired presentation ticket leave its successor
untouched. This does not yet qualify remote server response races.

Found dismisses native search before installing the accepted match connection.
After connection installation, an exact boxed JoiningGameSignal is posted through
the original nongeneric SignalRouter.PostSignal(object). Mode1 maps to loading
mode1; no forced FSM mutation is used. Posting earlier makes the original joining
state return to the menu because it has no active connection. The existing
StartJoiningGame delegate alone does not select the native loading presentation.
