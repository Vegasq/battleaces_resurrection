REQUEST AND STATE CORRELATION
Store each original native request and manager under strong GC handles, associate
its community request/invitation/lobby IDs, and defer all callbacks until enqueue
has returned. Reply uses partyLeaderHandle_ (RAW PlayerHandle); Invite/Cancel use
playerHandle_. Reply's original caller increments its pending counter AFTER the
enqueue call, so a synchronous synthetic response would corrupt native state.

The native directory is consumed in wire event order. The transport's latest
directory can already include a later departure; it is not a safe lookup source
for an earlier invitation event. Retain canonical names for outstanding invites.
Outgoing success uses automatedAcceptance=true as an explicit custom policy:
it preserves the existing host Party, while the recipient still must accept.
Remove a terminal sent request by exact original pointer, never RemoveAll(target).

Received native PartyInvite objects stay retained until their real reply can
capture GameMode. Same-sender re-invites wait for older reply callbacks. Duplicate
native replies each owe one counter decrement, but only the first reaches the
community server. Defer duplicate false callbacks until the primary finishes;
otherwise the native false callback removes the primary's invitation by sender.
Native wire statuses are mapped explicitly; their enum numbers differ.

Server acceptance must agree with the authoritative two-member lobby before
native accepted callbacks run. ProcessLobbyStateNotification does not reconcile
Party members or creator status; reconcile that separately through Party's
native constructor3e4c470. The joining guest's first state notification owns
manager Initialize and native CustomGameScreen navigation; do not initialize it
twice. Native GetCurrentServerTime uses an anchored DateTime and Unity realtime;
anchor both on presence installation and convert server remaining_ms on that
basis. The native countdown itself never expires/removes an invitation.

EXCEPTION AND RECONNECT REVIEW
The native reply callback decrements its counter before Party allocation/UI
events. Removing a C++ operation from its queue before that callback is useful
for reentrancy, but destroying it on exception loses the counter credit. Keep an
in-progress strong-rooted operation until completion, record its observed counter
delta, and let explicit reconnect settle only an unconsumed credit. A settled
credit must not receive another native decrement. Same-sender re-invites remain
blocked until all callbacks for the older invitation have completed.

Community reset must also complete the exact pending native Create (when still
retained), invoke the original LobbyClosed handler for an owned custom Party or
installed lobby, and verify cleared Party, prediction and pending Create before
dropping identities. Clearing adapter authority alone would leave stale native
custom state because the top-level menu FSM includes the custom-lobby screen.
Fault probes inject once immediately before or after the native reply callback,
then exercise the existing original reconnect-modal OnConfirm. Their results are
recorded as separate qualification; these flags are never used by normal play.

DEPARTURE / LATE ACCEPTANCE GUARD
LeaveLobby(false)3cab820 enqueues Leave at3cab945 then calls manager.Release at
3cab9a2. Release clears prediction at3cab171/175 and pending Create at3cab1bf/1c6;
it does not clear Front._party or Front.CustomGameLobby. LobbyClosed3e48ad0 clears
Party at3e48bb9. Consequently a queued Leave must suppress a subsequent accepted
notification and invite ACK callback even if the last authority snapshot still
matches. Keep wire ACCEPTED, remove the exact sent request and mark it applied;
there is no reply-counter credit owed by this host notification. Normal closure
owns final cleanup. Do not fabricate a decline or revive released prediction.
The --leave-on-accept probe invokes original Leave immediately before applying
the received ACCEPTED event, checks unchanged one-member departing Party and null
prediction, then verifies guest host-promotion and final cleanup. Reply ACKs use
ordinary FIFO timing for this case; INVITE/CANCEL ACKs retain350ms test delays.

REPRODUCTION AND LIMITS
Build client_patch/build.ps1 to a selected ignored build directory, then install
that helper with the patcher's --community-experimental option into an isolated
working copy. Never patch the untouched recovery directory. Run:
  python -m tools.verify_custom_invites --game <copy> --assets <local assets> --output local/<new run>
Add --completion-failure before or --completion-failure after for the two recovery
branches. Each run retains manifests, source digests, native/Unity/server logs and
a machine-readable verification report. Test process termination is not native
Quit validation. The test uses loopback development TCP, not a remote TLS session.
