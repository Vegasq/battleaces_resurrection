Native contract
The full CosmeticsUtils.ToProto(Cosmetics,ClientGlobalConfigDefinition) overload
is RVA3cc0940, token0600053d. Its other two-argument overload accepts a raw
CosmeticChangedEvent and produces a delta. The implementation resolves the exact
Cosmetics parameter class and verifies the original code pointer before invoking
the full overload through runtime_invoke. It derives a twelve-field ProfileCache
view; it never feeds that view through LoadFromProto, which clears the full list
and cannot preserve all seventeen slots.

The native account's existing Cosmetics object/subscribers remain authoritative
for the UI. Initial restoration runs before the local-menu ready marker. Later
observations run on the Unity thread before the client transport update and after
explicit diagnostic callbacks. The list identity,array,count and version bound a
complete copy; original installed FilterItem validates every selected item. The
observer sees both writes of an equivalent-slot swap after the callback returns.
Missing or zero local selections resolve to installed defaults. Complete saved
state must include every slot, with zero permitted only in genuinely empty slots.

Selection callbacks are four-byte item-key values, not boxed object references.
OnSelectItem updates the preview without equipping. OnEquipSelectedItem uses that
preview. OnSelectAndConfirm reaches the native equip/swap path. Equivalent-slot
swaps preserve the target's previous item. The existing picker must be reacquired
after each equip because its configured UI events may navigate or refresh it.
TryResetInvalidCosmeticsToDefault validates/repairs invalid items; it is not a
reset-all API. Native mouse/drag gestures are separate qualification gates.

Local configuration and storage
Optional client.json local_profile defaults to "default". It accepts1..48
lowercase ASCII letters,digits,underscore or hyphen; Windows reserved device
names are rejected. It is frozen when launching, independent of display_name,
online credentials and server changes. The TLS schema never receives it, and
enrollment preserves an explicitly selected key. This key currently isolates
cosmetic state only; native local deck storage is a separate remaining gate.

The working game's .battleaces-resurrection/profiles/<key>.cosmetics.json stores
schema1,build37822,the profile key,the exact runtime catalog SHA256 and all17
native-ordered [slot,item] pairs. No catalog rows or game assets enter source.
This is bounded canonical application JSON, not a general editing/import format:
reordered/escaped keys,duplicate fields,unknown versions,overflow,truncation,
wrong catalog,wrong slot,duplicate nonzero item and incomplete maps are rejected.
The twelve-field protobuf is a derived view, never the persistence format.

An ordinary local directory and profile writer lock are held while active.
Writes use a unique same-directory temporary file,FlushFileBuffers and atomic
MoveFileEx replacement with write-through. A failed save keeps the last file
and in-memory selection. Observed external changes are not silently overwritten.
Corrupt/mismatched/unavailable state disables writes for that session and retains
the input file; local play can still start with its current/default loadout.
No reparse-point destination is followed. Generated state is ignored by Git.
