CRASH169 - ATOMIC ARM PUBLICATION AND PROMPT REFUSAL
2026-10-24. Diagnostic handoff defect fixed and clean native exit verified.

Problem
The old clean01 owner opened native-crash169.arm directly for writing while the
game polled that final filename with GENERIC_READ and FILE_SHARE_READ. Windows
can reject this reader while a writer is open. The game permanently refused the
probe, but the owner stopped checking refusal after arming and waited60seconds.
Its log has "native crash gate unavailable" and NO trigger. The retained failed
run/forced cleanup is not evidence of a game hang after a crash.

The old native log did not retain its Win32 error. A deterministic Windows test
now reproduces ERROR_SHARING_VIOLATION(32) with that exact reader/writer contract.
This establishes the publication defect without inventing clean01's missing code.

Fix
tools/native_crash_gate.py writes the fixed authorization into a unique sibling
temporary,flushes/fsyncs,closes it,then uses Windows no-replacement os.rename.
The final filename is absent during writing. An existing gate is never overwritten;
failed writes/publications clean only their owned temporary. The native reader's
strict sharing,path,regular/single-link file,exact contents,thread/owner/mode and
original function checks remain unchanged. A refused open now logs the actual
bounded Win32 error before the existing permanent refusal.

tools/verify_native_crash.py promotes the clean diagnostic owner into source.
It requires an explicit --arm-native-crash and the owned local/r169g copy with
current helper provenance,a fresh private profile and a new output directory.
It checks refusal before readiness,before arming,throughout the exit wait and
after the retained process handle signals. A refusal exits the wait immediately.
Success requires one checked ready marker and one later original-thread trigger,
the expected native exception code,and complete natural root-only job cleanup.
It does not install exception handlers,invoke target APIs remotely or use Frida.
Historical private owner scripts and reports remain unchanged as prior evidence.
