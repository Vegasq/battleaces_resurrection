Native implementation
server/launcher/console_launcher.cpp is our small Windows x64 console launcher.
It resolves program/runtime/python.exe from its own module path and launches
that exact application without CMD,using -I -B -m tools.package_server start.
Forwarded UTF-16 args use CRT quoting,not shell expansion. Current cwd is retained;
default config still resolves from the package and explicit relative config keeps
its normal meaning. No global Python/PATH dependency or setup/network behavior.
Only three duplicated stdio handles enter the child through an explicit Win32
handle list. The child starts suspended,joins an unnamed kill-on-close job,then
resumes. Failure to assign terminates ONLY that just-created suspended child.
No foreign process enumeration/attachment or process-wide signal is used.

The parent consumes its own Ctrl+C with a custom process-local handler;it does
not set the inheritable ignore flag. Python receives the same original console
event and retains its SIGINT/asyncio/finally shutdown. Native launcher waits for
the Python exit and forwards its code. A bounded3s accounting check requires
zero live descendants/zero job-terminated children before returning success.
Abnormal launcher exit closes its owned job;leftover descendants fail rather
than being presented as a clean stop. This design does not qualify console Close,
Ctrl+Break,logoff,reboot,SCM or active-room shutdown under load.

Primary API behavior:
https://learn.microsoft.com/en-us/windows/console/setconsolectrlhandler
documents process-local custom handlers and inherited NULL-handler ignore state.
https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/start
documents /wait and /b Ctrl+C handling. Those mechanisms alone did not fix CMD's
batch confirmation in the actual isolated experiment.

Build and packaging
server/build_launcher.ps1 compiles /MT /EHsc /O2 /W4 /WX and runs an independent
CommandLineToArgvW roundtrip across empty,Unicode,whitespace,quotes,trailing
slashes and literal shell-like args. Its receipt binds all four source/build
files and the argument-test result to the executable hash. Package builder
requires AMD64 PE32+ console/non-DLL shape,our ABI marker and exact current
source/test receipt before output. Source binaries/receipts are ignored build
outputs;the delivered package includes Start Server.exe plus immutable
program/launcher/launcher-build.json. No Start Server.cmd is generated.
