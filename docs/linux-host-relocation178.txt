Source changes
- tools.host_relocation reads bounded,duplicate-free config;preflight rejects
  Windows drive paths before Linux launches Wine and names missing path fields.
- Explicit tools.linux_server relocate --host-dir maps paths inside one standard
  old Windows host root into the copied host. It validates staged config and
  requires copied data/TLS paths,backs up exact old bytes,then atomically replaces
  only config/host.json. Other settings,private-key bytes and player files remain.
  Already-portable config is checked without rewriting. Missing files,custom
  external paths,escape attempts,invalid options and observed concurrent edits
  refuse without replacing config. A failed final replace retains the backup.
  Both hosts must be stopped;no cross-OS lock exclusion is claimed.
- prepare-prefix --host-dir <host> --root <new-directory> verifies the copied
  package/config,creates a new persistent win64 prefix and retains prefix-check.log.
  Requires exit0,exact BA_WINE_READY line and system.reg before writing a shell
  launcher. The launcher binds the copied host and chosen prefix. No game export,
  server listener,certificate regeneration or existing-prefix reset occurs.
- start/check accept --host-dir,validate paths before Wine and explain missing
  prefixes. Normal fresh-install setup remains supported using the pinned174
  package and one-time graphical export. The copied-host route needs no export.
- New server.rc_host first-run configs use relative assets/data/TLS paths for
  same-drive layouts. Explicit assets on another Windows drive remain absolute.
  Staging now happens beside the final config so relative-path validation uses
  the correct base. Existing configs are never rewritten by first-run setup.
