BUNDLED SERVER / NATIVE MULTIPLAYER QUALIFICATION -- 2026-10-19

Scope
This closes the gap between separate source multiplayer controls and bundled
local gameplay. tools.verify_packaged_multiplayer launches a bundled Windows
host and two separately configured bundled production clients against one
numeric-loopback TLS listener. Actual worker/simulation/queue clocks are kept.
The first control is full-human1v1;partial2v2 and2vAI are supported test modes.
Protected credential deployment,actual CMD mouse play,clean-PC,physical input,
audio/visuals and Internet/cross-PC acceptance remain separate requirements.

External adapters and credential boundary
tools.packaged_network_drivers is authored qualification code,not shipped in
either product package. Each child uses isolated bundled Python,foreign cwd/
PYTHONPATH and a PATH containing System32 only. Imported production modules
are inventoried and hash-checked. No source-checkout module substitutes for
host/client/bridge/TLS/native-worker production logic.

The restricted tool token's earlier Windows-error5 protected-enrollment blocker
is already documented;do not retry it or weaken the owner/SYSTEM DACL. This
control explicitly uses stdin-only ephemeral test identities. Host CredentialStore
is replaced ONLY inside the external driver by an in-memory fixture;the client
adapter supplies the same fixture when its production resolver reads its fixed
nonsecret placeholder invite path. Both still use actual TLS verification and
production admission/authentication/private bridge logic. No token is passed on
CLI,written to config/invite files,or intentionally logged. Retained public
outputs are checked for accidental fixture-token disclosure. TLS test keys are
generated under this ignored owned output and removed after the run;no host
trust store is changed.

Production host health prints credential_store_checked=true when list_public
returns. UNDER THIS ADAPTER that Boolean refers to the in-memory fixture check;
it does not qualify protected filesystem credentials or their DACL. Report scope
and fixture_store make that limitation explicit. Final real enrollment remains
required before release;this adapter is not a product fallback or setup option.

The host executes original server.host.run,configuration/assets/storage/native
startup checks,and default TLS coordinator with its native match worker. A
constructor observer keeps the original constructor and audit callback,recording
the frozen public roster/decks/loadout seats. A worker-create observer forwards
unchanged arguments to the original factory and records actual bundled worker
identity/backend/cleanup. Neither observer accelerates or replaces simulation.
Host stop cancels its original run task and awaits normal finally/worker/listener
cleanup;forced process termination cannot qualify a passing run.

The client executes production client.main,optional-settings resolver,verified
TLS transport and inherited bridge. An external spawn adapter first checks the
ordinary player arguments contain no automation,then adds explicit original
Play/build/surrender/Continue/search/Quit diagnostics. A shared owned gate starts
Play only after both native menus are ready. The second client's original deck
edit verifies independent human selection. Public full groups must launch
promptly;partial groups must retain the real30-second deadline and timer.

Owned original Quit gate
The helper adds -native-quit-gate-smoke ONLY for this explicit native Quit probe.
It waits for fixed native-quit.ready under the validated owned nativestest_
profile. The gate must be an empty ordinary single-link file. Ordinary Start
Client never supplies the flag or creates/releases the gate. The verifier writes
it only after BOTH public returns and server queue/room/worker cleanup. Original
menu/model/ownership/navigation/asset checks then run unchanged,followed by the
original Show/Confirm callbacks. The original60-second Confirm exit bound remains.
The gate does not bypass active-world/idle-menu validation or force Quit.

Required native evidence
- One offer,match,completed result and released native match worker;both
  authenticated identities share it with expected human/bot seats and frozen
  full loadouts/configured names/independent decks. Full/partial queue timing
  must match policy using original real performance timestamps.
- Both actual clients receive the complete contiguous authoritative frame
  stream;every recorded receipt hash matches the bundled host's frame hash.
- At least20 common observable-state samples per client agree with original
  server simulation. This is sampled canonical visible-state agreement,not an
  independent full hidden-state/determinism proof.
- Original build callback queues normally,original public results/Continue
  return each remote world exactly once;no local-AI fallback may satisfy this
  multiplayer control. Native elapsed search samples must agree with wait mode.
- Completed return precedes the explicit gate and original idle Quit. Exact
  native five-event Quit trace,game+launcher exits0,and zero active owned job
  descendants BEFORE close are required. The host listener must close,its state
  lock must release,and health/match workers must exit0 without failure.
- Profile-local native TOML and structurally valid replay are retained. Three
  named shared TOML/replay/backup inventories,config,adapters,packages,assets and
  bound source remain unchanged. Source/game assets/keys/private captures never
  enter Git. Existing manual24 and original/frozen copies remain unchanged.
