Authoritative storage
Profile schema2 contains exactly schema,profile_id,deck,cosmetics. The cosmetics
object contains catalog_sha256 and all17 native-ordered [slot,item] pairs. Both
the deck and every cosmetic slot pass installed-catalog validation before one
atomic profile replacement. Portrait,banner and entitlement bytes are rebuilt
from validated slots; a caller cannot override them by forging derived fields
in an otherwise valid snapshot. Returned ProfileState/CosmeticSnapshot objects
and their selected tuples are immutable.

Schema1 deck-only profiles remain readable. With a verified cosmetic catalog,
they acquire installed defaults in memory without rewriting the input file.
Their next save or full snapshot restoration writes schema2. Old deck-only save
callers preserve the existing complete cosmetic selection. Corrupt,mismatched,
incomplete or duplicate-slot records are rejected and retained on read and save.
A reader without the catalog cannot load or overwrite a schema2 record.
Profile identity remains the authenticated server ID,not display_name or the
client's separate local_profile key. All profile input remains bounded to4KiB.

Snapshot envelopes now support schema2 full profile records; catalog-less
deployments keep the existing schema1 deck mapping. A complete snapshot is
bounded to8MiB to accommodate4096 full profiles plus the existing1MiB hash-only
invitation database. Compatibility includes the verified cosmetic catalog hash
and the hash of the whole imported asset inventory. Every record is validated
before a restore directory is created. Restored profiles are read back in full
before host.json is published last. Old schema1 snapshots with exactly matching
assets restore installed defaults when a catalog is available. Older snapshots
whose asset inventory differs still require their matching bundle: restore first,
then explicitly upgrade the assets/profile format. No unchecked compatibility
relaxation or automatic catalog substitution is introduced.

Selection ownership and match construction
Registration retains a validated immutable cosmetic selection with the session's
deck. A public queue Entry freezes both at entry,before waiting or proposals.
Custom rejects selection changes during start/loading/running; room creation
uses the connected session's chosen deck/cosmetics rather than reloading a later
disk edit. Rematch takes a new snapshot of the connected selections. A new human
join is fully validated before peer/seat/queue ownership is committed.

GameTemplate.build_match requires a verified catalog and exact human-slot map
when cosmetics are supplied. It revalidates each snapshot's complete slots and
catalog identity. Every human army receives explicit portrait/banner fields and
one service0 entitlement with item IDs in native slot order. Emote order is not
sorted or deduplicated. Full17-slot immutable snapshots remain available in
MatchData even though the native entitlement omits truly empty slots. Bot deck,
identity and strength selections stay independent and retain original bytes.

JoinArmy retains strict units,ability groups,army and portrait/banner validation.
Structurally valid client entitlement metadata is replaced with the server's
frozen deck before canonical frames reach native simulation or peers. Malformed
protobuf is rejected before that step. Bot identities cannot enter this human
input API; the server uses its existing BotRoster path for their inputs.

Installed export/import
The ordinary explicit server-assets export now waits for CosmeticSlot as well as
the other loaded tables. It serializes the native17-slot compatibility matrix
twice,requires byte-for-byte equality,and includes cosmetic-catalog.json in the
completion manifest written last. This does not require experimental unlock or
equip flags. Import verifies the enclosing size/hash and strict inner catalog.
The host rechecks file hash/item count/slot count and consistency with bot item
IDs and portrait/banner pools. Old complete bundles remain usable for their
original scope. New bundles include the catalog automatically; no installed
catalog rows,game assets or generated selections enter Git.
