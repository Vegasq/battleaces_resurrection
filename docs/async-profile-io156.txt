Cancellation/departure semantics
A cancelled waiter does not undo a filesystem write already submitted. That write
remains server-owned and drains;subsequent reads/writes follow it in the FIFO.
No stale session/lobby/room mutation or success ACK follows the cancelled/stale
operation. In particular,a departed-lobby refusal can follow an authorized write
that finished on disk;it must not mutate a later lobby or roll back newer data.
Actual storage failures preserve the prior file and produce a refusal,not a queue
ticket/world. The regression controls distinguish those cases.
