PUBLIC TEAM DISCONNECT RECOVERY
Updated:2026-10-19 UTC. Automated graphical clients on one Windows PC.

Implementation and evidence boundary
tools.verify_public_clients now accepts explicit --disconnect loading|running.
It closes only the first owned client's current server TLS peer after every
human has joined the same assigned match. Loading injection requires no loaded
acknowledgements or native world-ready markers. Running injection requires every
human's loaded acknowledgement and at least201 received frames. The actual queue
clock and server timeout policies remain unchanged.

The disconnected client must invoke the original modal OnConfirm, defer release
of that invoking modal to a later update, run original CleanupGameState, release
its world and retire its ticket at an idle menu. Surviving clients must process
the authoritative abort, return at nativeIdle=1 and receive their RETURN ACK;
their existing community sessions remain open with no assigned room. Exactly one
offer/worker/match is allowed, with one abort and no completed result. Committed
matches must not fall back to independent local worlds. All queue/offer/room/
worker capacity must release. These checks retain normal completed-match checks.

Running receipts must be contiguous prefixes matching the authoritative frame
hash journal. Loading aborts must have zero native and authoritative frames.
Only the injected victim may report the two known connection-loss stop reasons.
Unknown native failures still fail the probe. An interrupted native IPC request
may produce worker exit1/CancelledError: under the existing kill/reap policy;
that exception is allowed only for the identified injected running match, with
its worker_released event and complete process/thread/cleanup reaping. Other
worker failures and normal completed-match nonzero exits still fail.
