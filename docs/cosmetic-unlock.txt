Updated:2026-10-19 UTC. Picker/model qualification; equip/persistence remain open.

Activation and boundaries
The installer accepts --cosmetics-experimental only with a helper exporting all
six scoped wrappers. It guards12 call/tail sites and one owner-argument change
against exact supported original bytes, then records them in the patch manifest.
The helper separately requires -local-cosmetics-experimental. Normal Start Client
does not add that flag, diagnostics, captures or automated UI actions. Only the
disposable test copy was patched; manual/frozen and untouched copies stay intact.

The loaded item/slot tables remain authoritative. Initialization validates their
category/default rules and roots the owned Front,account and Cosmetics. An atomic
owner-thread gate prevents other native threads from inspecting Unity roots or
mutable catalog data. Known cosmetic entitlement keys can pass the picker index
check and cosmetic-only ownership checks. Unknown keys retain the original signed
dictionary result/Steam semantics. Original shared dictionary,Steam inventory,
unit ownership,category filters,equip and equivalent-slot swap bodies stay intact.
Item-model projection calls original CacheEntitlementData first,sets Owned for
known installed items,and preserves its resulting Rarity. No inventory entry is
added or purchase/grant API called.

Three scoped side-effect wrappers defer selected-deck publication,Steam presence
and retired-front cosmetic save requests. They do not implement persistence yet.
The final SaveCosmeticLoadout branch is a tail jump. The original SaveAllCosmetics
serializer now reaches this wrapper with a valid case37 consumer,which is consumed
without entering shared Enqueue. Unexpected owned request shapes fail closed.
The two Changed-callback wrappers are installed/byte-checked but still need actual
equip/swap qualification. Suppressing SetBannerAndPortrait does not remove the
SteamRichPresence class constructor's Application.quitting subscription.
