REMOTE / LOCAL MATCH TRANSITIONS
Updated:2026-10-19 UTC. Failed/completed1v1 transitions qualified; not release acceptance.

Existing application contract
client_lifecycle.prepareLocal requires no world owner and no active public intent,
then retires community control at an idle menu and restores the application-local
identity. Local Try Deck retains the native selected deck and runs its own AI
world. practice_ai.release requires an idle native world, zero AIManager world
and an empty AI-player collection before freeing roots and releasing the local
world lease. A later public Play requests a fresh authenticated connection and
submits the retained local deck. These are existing production ownership rules.

Native diagnostic extension
verify_public_clients --practice-between requires the separately gated remote
retry flow. After the first remote match fully retires, a third ordinary-file
gate permits the original Edit Deck / Try Deck callbacks in each same process.
practice_ai smoke remains suppressed during public search or world ownership.
Only explicit public/practice transition smoke flags allow this new sequencing;
ordinary launcher/gameplay behavior is unchanged. The normal shared gate and
practice gate each keep their180-second bound. Only this explicit probe's final
retry gate allows600 seconds while local AI combat is being qualified. Server
queue deadlines, input timeouts and readiness rules are unchanged.

Before the final remote gate opens, each local match must produce owned bot
supply and demonstrate both autonomous Move/Attack orders and changed positions
for the same produced unit IDs. Native snapshots must retain the configured
human name and the exact deck from the first remote assignment. The original
local result/Continue must run once and release the local world/AIManager.
No new remote connection, authentication, room or worker may occur during local
practice. Community presence must be fully retired. Final remote Play must use
new sessions, keep those same names/decks, deliver exact canonical frames and
native builds, finish original result/Continue, and release all owned capacity.

This differs from direct team retry: direct retry preserves survivor connections;
entering offline practice intentionally retires them. These expectations are
checked independently. Merely returning to an idle menu does not prove combat,
mode switching or cross-process persistence.
