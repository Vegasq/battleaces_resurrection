Configuration and trust

and fill every field. Paths are resolved relative to that config file. server_host
and server_port select the route; server_name is the expected certificate DNS/IP

Private IPC version1
 u32 little-endian body length, u8 version1,u8 kind,u32 nonzero session ID,payload.
 Kinds:OPEN1(no payload),DATA2(1..65536 bytes),CLOSE3(no payload),FAILURE4(one byte).
 Body is6..65542 bytes; the size is checked before allocation/read. OPEN IDs must
 increase exactly by1; retired-session traffic is discarded and future IDs fail
 closed. The game never sends FAILURE. Failure codes1..7 mean certificate/TLS,
 connection,authentication,identity,queue,internal or timeout failure.
 No invitation,certificate,key or token is carried in this protocol.

Private IPC version2 (implemented opt-in foundation,2026-10-18)
The source launcher accepts --dynamic-identity-experimental. It requires the
helper's BA_RESURRECTION_TLS_BRIDGE_V2 marker before spawn, passes
-secure-transport-version=2 and omits startup -player-id. ABI1 remains the default
for existing launchers/frozen packages; there is no protocol auto-downgrade.
Version2 keeps the same bounded frame layout and monotonic session IDs. It adds
READY5 containing exactly34 ASCII bytes:p_ followed by32 lowercase hexadecimal
digits. Only the parent may send READY, after verified TLS and AUTH_OK matching
the private invite's identity. The native helper waits before constructing HELLO
and checks community welcome against this session's authenticated identity.
READY must occur once for the active session. DATA before READY,duplicate or
malformed identity,future sessions and version mismatch fail closed. Valid retired
frames cannot change a current identity. End/begin clears the previous identity.

The v2 Bridge accepts an async Remote resolver. It runs on each OPEN with a5s
deadline; cancelled requests do not progress into TLS/AUTH. RemoteConfigResolver
reads schema2/CA/private invite in the parent on each attempt, validates all
settings and pins game_directory to the launched installation. Local file reads
run off the event loop and perform no network operations; cancellation discards
their eventual result. Missing config/CA/invite emits fixed availability code8;
invalid local settings emit9. Existing codes1..7 retain their meanings. Raw local
paths,parser errors and credentials are never sent over the inherited channel.
Failed attempts leave that channel usable for a later OPEN. TLS hostname/CA,
strict private-file loading,AUTH and server identity checks are unchanged.

The experimental source launcher still needs an initial schema2 game/settings
file and uses the existing dedicated menu/recovery flow. It is not the final
offline-first Start Client. Optional connection failures still need separation
from match-world failure; see unified-client.txt. No public fallback/team mode
or new graphical lifecycle qualification is claimed by the bridge tests.

Native wire/input queues are capped at2 MiB. The parent holds at most64 pending
game chunks and2 MiB payload per session, plus bounded in-flight/stream buffers.
Writes/drains have5s deadlines. Remote TCP/TLS and AUTH use the existing bounded
helpers. The native secure welcome deadline is30s. A remote EOF closes only that
session; loss of the private process stream requires relaunch. Closing one session
cancels/drains its relay tasks and TLS stream before the next is created. Revocation
is checked again on the next session; it does not evict an established match.

The socket pair is explicitly IPv4 loopback, created before spawning the game.
STARTUPINFO.handle_list restricts inheritance to that endpoint; the helper clears
its inherit flag, validates a connected loopback stream, and uses nonblocking I/O
on the game thread. This is process-local capability isolation, not protection
against an administrator/debugger or a compromised same-user game process. The
local traffic is game data only; internet traffic travels through verified TLS.

Failure qualification (use a fresh run name and allow for cold startup):
 --pre-match-failure unavailable      refuse client0's first TCP connection
 --pre-match-failure authentication   reject client0's first test invite admission
 --pre-match-failure lobby            abort client0's authenticated lobby stream
 --disconnect-frame 100              abort one running-match stream
 --postgame-error                    send ERROR after both native result screens
Choose one fault mode. Each recovery test requires original Reconnect,its return
before deferred modal release,an unready lobby and a separate Play action. Initial
faults leave client1 connected and require one matching completed game; postgame
requires two. All use real local TLS/admission and fixed test-only fault injection.
Pre-match faults cannot be combined with delay/jitter shaping.

Adding --quit-on-failure to a mid-match/postgame fault instead invokes each exact
owned dialog's original OnCancel. Both process handles must exit naturally with
code0; any harness termination fails this qualification. After both callbacks,
shutdown has a separate60s bound. The first native Quit run failed (processes
remained alive); see client-session-lifecycle.txt. These options require a helper
with the matching diagnostic flags. They do not enable release auto-retry/auto-quit.
