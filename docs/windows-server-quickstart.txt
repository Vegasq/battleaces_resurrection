BATTLE ACES RESURRECTION - RC1 WINDOWS HOST

Import your locally owned build37822 assets using section1 below. Then double-click
Start Server.exe. If config/host.json is absent,it creates an RC open-access config
and self-signed certificate automatically using built-in Windows cryptography.
No OpenSSL installation,CA distribution or player invite issuance is required.
Players enter only this host's IP in client setup. Default TCP port:47623.
Stop normally with Ctrl+C. Existing config/data are preserved on later starts.

RC1 encrypts transport but clients do not verify the server certificate. Anyone
who can reach this host can join. Configure normal Windows firewall/router access
for the intended network;the program makes no automatic firewall/trust-store/NAT
changes. Host config schema2 uses access_mode:rc-open,certificate/key paths and
credential_directory:null. Server identity keys are generated locally,never shipped.
Keep program/,assets/,config/ and data/ separate as described below.

Existing schema1 verified/invite host configs are NOT changed automatically.
The certificate/invite provisioning in section2 below is the optional verified
mode reference,not an RC1 prerequisite. Remaining clean-PC/service/Internet and
physical acceptance gates remain recorded in the delivery plan.

VERIFIED/INVITE HOST REFERENCE

This is a development preview for Windows x64 and game build37822. It has not
passed clean-PC or outside-network release acceptance. Do not expose an
unauthenticated listener. The included Python runtime needs no installation.
No game files, server certificate, private key or player invites are included.

Extract the complete archive into an ordinary local folder. Keep program/,
assets/, config/ and data/ separate. Run the following commands in Command Prompt
(cmd.exe) in that folder. After configuring/importing the server as below, Start Server.exe
starts it directly. BattleAces-Server.cmd without arguments prints help. Existing files are not upgraded in
place: extract future versions to a separate folder and retain your local data.

  BattleAces-Server.cmd verify

The integrity manifest detects missing/changed files. It is not a digital
signature: obtain the archive and its SHA256 from a trusted project release.
The Python license is program/runtime/LICENSE.txt. Program files are read-only
inputs during operation; config and data need the host account's appropriate
permissions. Avoid network shares and paths with links/junctions.

1. IMPORT YOUR LOCALLY OWNED GAME ASSETS

Use the matching client patch package on a working copy of build37822. Close the
game before installation; preserve your untouched recovery copy. After patching,
run the following in the working game directory and wait for the export manifest
to contain complete:true, then close the game:

  "Battle Aces.exe" -offline-practice -export-server-assets -local-profile=asset_export

The helper writes server-assets/export.json and its declared files relative to
the game directory. If export fails or never completes, stop here; do not invent
or reuse an incomplete map/catalog. For an already patched copy, supply its
verified original backup in the import command:

  BattleAces-Server.cmd import-assets --game-dir "<working game>" --export-dir "<working game>/server-assets" --original "<working game>/.battleaces-resurrection/original/GameAssembly.dll"

Run that import command from the extracted SERVER package folder. The export
profile asset_export keeps the exporter's native settings and backup separate
from your normal player profile. No match starts in export mode. Use a fresh
export directory for each export: the exporter replaces its declared outputs.
For example, add -server-assets-dir=server-assets-new and use that directory in
--export-dir. Do not run another game instance from the working copy during export.

The importer checks exact original DLL/metadata/simulation hashes and the export
manifest. It creates assets/build-37822 with the simulation, original mode maps,
catalogs and generated descriptors. Current source exports also include the
original AI DLL,validated rule profiles and compatible bot identities/decks.
Offline public/team modes have bounded native qualification;full multiplayer
release acceptance remains open. Older preview packages
only support their documented export format. Import refuses to overwrite a
nonempty destination. You can
perform the import on your gaming PC, then privately copy only the resulting
assets/build-37822 directory to the host. A full graphical game installation on
the host is unnecessary. Never upload imported assets as project releases.

2. CONFIGURE THE HOST AND PRIVATE PLAYER ACCESS

Copy config/host.example.json to config/host.json. Paths in this file are relative
to the config directory, regardless of the terminal's current directory.
Set listen_host (numeric IPv4 bind address), listen_port, asset/data directories,
certificate_file, private_key_file and credential_directory. Default port:47623.
The server certificate must be valid for the DNS name/IP used by your players.
Provision a server certificate/key and trusted CA using your normal certificate
tools; share only the CA/public certificate with players, never the private key.
The host requires certificate verification on clients. There is no insecure
internet fallback or automatic firewall/port-forwarding change.

Issue one invite per player. Create the output's parent directory first. Invite
contents are stored with a protected owner/SYSTEM DACL, never printed as tokens:

  BattleAces-Server.cmd credentials issue --out "<private local folder>/friend.json" --label "Friend"
  BattleAces-Server.cmd credentials list
  BattleAces-Server.cmd credentials revoke <invite-id>

If credential_directory differs from the default, use credentials --store
"<configured directory>" before the issue/list/revoke command. Run issuance and
hosting under the same intended Windows account. A private-permission error is
fatal; do not grant broad access to work around it. Give the individual invite
to its intended player through a private channel. It does not belong in Git,
screenshots, public chat, logs or command-line token arguments.

Give each player the server address, port, certificate DNS/IP name, public CA file
and that file's SHA256 through a trusted channel. In PowerShell:

  Get-FileHash -LiteralPath "<public CA file>" -Algorithm SHA256

This is a hash of the entire file, not a certificate thumbprint. Preserve the
exact bytes during transfer. Players use their package's Connection Setup to
confirm this hash, import their downloaded invite into a protected local copy,
and test TLS/authentication before playing. The host's file ACL does not transfer
between different Windows accounts; players should import, not weaken the
runtime credential check. No server private key is needed by a player.

  BattleAces-Server.cmd check
  "Start Server.exe"

Check verifies local configuration, asset hashes, private credential access and a
native worker's create/step/shutdown cycle without opening a public listener.
Start repeats this check, then listens. Success proves local readiness only;
test connectivity from a second PC before setting up remote access. For private
internet hosting, separately configure TLS, a narrowly scoped TCP firewall rule
and router forwarding for your chosen port. Those changes are not made by this
package. Actual cross-PC/internet acceptance remains open.

3. OPERATION AND DATA

Use Start Server.exe and Ctrl+C in its console for orderly room/worker shutdown.
The native launcher waits for the bundled Python host,passes its exit code and
owns its descendants. There is no batch termination question after Python exits.
Optional Windows
service setup is in SERVICE.txt. The service adapter uses the bundled runtime,
checks native readiness before reporting RUNNING, and drains rooms/workers on
Stop or Windows Shutdown. It must run under the account that provisioned its
private files. Service registration is a separate administrator action; actual
SCM/account/reboot qualification remains pending. service-command prints the
exact registration settings without installing or starting anything:

  BattleAces-Server.cmd service-command

Do not register the console start command or the CMD wrapper as a service.
Start/check/backup exclusively lock the configured data directory. A second
host or maintenance command cannot use it while the first host is running.
The one-byte .host.lock remains after shutdown; its presence is normal. OS locks
release after process exit/crash. Do not delete or replace it to bypass an active
host. These guarantees apply to the packaged host, not unrelated developer tools.

Normal local diagnostics omit per-frame events. diagnostic_audit:true enables
additional local event/state records; no uploader is configured. Event logs rotate at
log_max_bytes (default8 MiB), retaining log_backups (default4) plus the active
file. Raw packets, maps and snapshots are not written by this host entry point.
Profiles are in data/profiles; native workers use data/workers. The native DLL may
create an empty sim.log there; its independent file/console sinks are disabled
before SimInit. Native callback history is kept in a bounded in-memory deque.
High-detail
diagnostics can affect timing and are unnecessary for ordinary play.

4. BACK UP AND RESTORE PLAYER STATE

Stop the host with Ctrl+C (or Stop-Service for an installed service), wait for it
to stop, then create a new snapshot under the same Windows account:

  BattleAces-Server.cmd backup --out "backups/weekly.backup.json"
  BattleAces-Server.cmd verify-backup --input "backups/weekly.backup.json"

The snapshot stores saved decks and the hash-only invitation database, including
stable player identities and revocations. It contains no bearer invite files,
game assets, logs, host settings or TLS private key. Its output directory/file
is created with protected owner/SYSTEM permissions; existing output is refused.
Keep snapshots private. The checksum detects accidental changes, not a malicious
replacement from an untrusted source. Keep your host config and server TLS key
separately in protected storage, and retain or re-import matching game assets.

Restore into a NEW directory; even an existing empty destination is refused:

  BattleAces-Server.cmd restore --input "backups/weekly.backup.json" --destination "restored-server"
  BattleAces-Server.cmd check --config "restored-server/host.json"
  BattleAces-Server.cmd start --config "restored-server/host.json"

The current --config supplies host settings and trusted asset/TLS paths. Restore
validates snapshot integrity, exact asset compatibility, decks and credentials
before writing. It creates new data/private storage for the current Windows
account, then writes the new host.json last. The existing config, profiles and
credential store stay unchanged. A failed restore retains its incomplete new
folder for inspection without a runnable host.json; retry with a new destination.
It does not edit Windows ACLs or turn off runtime credential checks.

On another host, first supply matching assets and configure your TLS paths, then
pass that configuration with --config to restore. Paths in the new host.json are
absolute; review them when moving it. No automatic start or switch is performed.
Restoring rolls invitation validity/revocations back to the snapshot time. Review
credentials list and reapply later revocations before accepting connections.
Normal-account Windows permissions and clean-host restored play are separate
qualification gates still open for this preview. Service restart remains pending.

Development-only plaintext requires allow_insecure_loopback:true, numeric
127.0.0.1 and all three TLS/credential fields set to null. It cannot bind a LAN
or internet address and is not used by the secure client launcher.
