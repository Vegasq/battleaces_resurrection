Architecture
The shipped aiprogram.dll has14 exports and supports four army contexts. Static
evidence and two-army execution support one authoritative Simulation.dll world
plus one separate AI decision world in an isolated worker. Multiple bots can
emit ordinary commands into that one match. This is the candidate for preserving
partial human groups when public queues fill remaining seats with AI. Separate
local matches for those humans would not satisfy the product requirement.

The AI world is not a second combat simulation. AIInit is process-global; call it
once per worker, retain distinct AI/Simulation handles, serialize native calls,
and destroy bot registrations/worlds before process teardown. The alternative
fuzzylogicai.dll has only seven exports and is not this interface. Static imports
are KERNEL32-only. Headless execution passes on this PC from locally imported
assets; clean-PC deployment and actual service-account qualification remain open.

Inputs and ownership
SimCreateWorld consumes raw GamePb.GameData, as the existing server already does.
AICreateWorld consumes raw GamePb.GameConfig and a native MapFrame FlatBuffer.
Use the final mode/roster/alliance/deck/seed configuration, not gzip or a MapConfig
protobuf. Simulation exposes SimGetMapFrameSize/SimGetMapFrame for the map bytes.
The AI config importer reads four army contexts and eight deck slots; an invalid
deck can silently zero its deck even when the call returns success. Verify actual
production, and never assume a later JoinArmy repairs the AI's initial snapshot.

AIUpdateRule requires a fully materialized Uncapped.Flatbuffers.Fuzzy root. Its
nine vectors contain unit/HQ/ability/tactical rules, fuzzy sets, unit AI floats,
unit tags, crisp weights and allowed units. The original BuildFlatBuffer also
uses global UnitTable AI metadata and overrides. A profile ID or partially decoded
tuning asset is insufficient. The native wrapper ignores its length argument;
only validated exact-build blobs may cross this boundary. Preserve the original
default rules for all armies followed by selected bot-profile rules. Empty
tactical vectors replace previous rules; they do not inherit working tactics.

The client server-assets exporter now calls the original BuildFlatBuffer /
ToSizedArray path for every enabled mode1/2/4/5 profile plus the real default.
It exports59 complete blobs and a local ai-rules.json manifest; default profile4.
Every blob is serialized twice within the same loaded process, and manager world,
frame, player count, simulation reference and profile selections are unchanged.
Repeatability is explicitly scoped to that process. FuzzyRules.id comes from
UnityEngine.Object.GetInstanceID, so bytes/hashes differ across client launches.
Preserve each local manifest's actual hashes rather than pinning one universal
profile hash. Cross-process semantics and native execution are compared below.

Admission and import
server.ai_rules walks every table/vector, requires native-dereferenced vectors,
checks object spans/overlap, signed vtables, offsets/alignment, bounded aggregate
counts, category-specific input/output domains and native enum array indices.
Floats must be finite and strictly between-2^31 and2^31 for native Q32.32
conversion. Fuzzy/crisp IDs are unique and non-Custom fuzzy references must
resolve. Valid empty vectors and shared/negative-offset vtables are preserved.
RuleBook checks exact build/DLL identity, filenames, lengths, hashes, unique
profiles and default membership. Import verifies every rule entity against the
same full GameConfig. These checks do not authenticate arbitrary supplied rules
or establish useful tactics: admit locally exported exact-build content.
The source tests use authored synthetic data; real rule blobs remain ignored.
Static schema/corruption evidence:local/server-ai-validation01 (59 valid exports,
44 corruptions rejected). No copied rule/asset content enters source fixtures.

Frame and command contract
The native client updates AI every five simulation frames. It feeds Presentation
label registry3, Unit registry1, enemy spy views and each bot's own view, then
AIStep(50) at a normal50ms simulation step. The argument remains50, not250.
Simulation frame generation takes an ALLIANCE; AIUpdateSimFrame/AISpyOnSimFrame
take an ARMY. Preserve the authoritative army-to-alliance mapping and original
view/spy permissions. Adding an AI army does not replace its normal JoinArmy.

GetAIInputAction returns a status, not a byte count. Its output is a varint body
length followed by one GamePb.InputActionQueue (repeated InputAction field1).
Parse only that bounded body, preserve commands, and wrap them in the bot's own
InputActionsByPlayer identity before committing canonical simulation input.
The native reader consumes queued commands even if the buffer is too small;
there is no size-query export and retrying a small read loses commands. Worse,
its size comparison excludes the varint prefix. Allocate prefix guard space,
use a deliberately bounded sufficient capacity and qualify heavy-army output.
Status0 alone does not prove complete command delivery. The original managed
bridge uses4096 bytes; this is an observed choice, not a proven safe upper bound.

The implemented wrapper uses1MiB body capacity plus ten prefix bytes and a
16-byte canary. It detects unwritten, malformed or oversized queues and retains
every InputAction in the bounded body. Map/label copies are serialized with
simulation mutation. AI initialization requires the exact configuration hash of
the still-unstarted simulation; armies/alliances/profile rules are validated.
