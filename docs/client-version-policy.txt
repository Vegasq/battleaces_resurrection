CLIENT VERSION POLICY AND PERSISTENT UPDATE OVERLAY
2026-11-08. Paired0.3.0-rc1.10;deployed owner-only,not publicly published.

Behavior
The native helper sends client compatibility revision1 as a four-byte trailer
on its existing dedicated/community HELLO. Protocol3,original game/simulation
hashes,community versions and player identities keep their existing checks.
An absent trailer is legacy revision0. Extra/truncated trailers are rejected.
Newer compatible revisions can connect;client/server package version strings
do not have to be identical.

The host defaults to minimum_client_revision1. After TLS authentication and
validating HELLO,the server rejects older revisions before reserving a player
identity,writing a profile,registering presence,creating a room or worker.
The error contains the bounded BA_UPDATE_REQUIRED/minimum/message policy.
client_update_required audit events record observed and required revisions.
The client displays the message through the existing top-center status strip.
Its separate persistent notice survives normal loading/error expiry,local
practice and return to menu. It never captures mouse input or owns a match.
Only a successful server welcome clears it;ordinary connection failures do
not erase a prior update warning. The existing local AI fallback remains.

The persistent overlay uses a720x84 panel/font20 rather than the normal
560x54/font22 loading strip. Messages are plain text with rich text disabled.
The configured message is bounded to1..160 printable ASCII/newline characters.
There is no automatic download,installer execution or clickable link in this
overlay. The native original login/compliance service remains disabled.

Settings in config/host.json (both are optional with these defaults):
  "minimum_client_revision": 1,
  "client_update_message": "Client update required (0.3.0-rc1.10). Download the latest installer from GitHub Releases."
Set minimum_client_revision0 only for a deliberate legacy-compatible rollout
or rollback. For a later required revision,change the message to name that
release too. Invalid/bool/negative/overflow revisions and invalid text fail
configuration validation. Packaged compatibility.json records client_revision.

Rollout
Publish the paired installers before enforcing a revision that is not yet
available for download. A staged server can accept legacy clients with minimum0
while clients are upgraded;set minimum1 to require this corrected helper.
Before enabling the policy on the public host,retain the host configuration
backup and the existing owner-only firewall until N20 accepts movement.
The owner-only live host now runs rc1.10/minimum1. The existing N20 request
now points to final client-installer02,which matches this server. Publication
and public reopening remain pending;live-server-rc110-20261108.txt.

An old server rejects this new HELLO trailer as "extra hello fields". Updated
clients map that incompatibility to a persistent "Server update required"
warning and retain offline AI. Existing released clients do not contain this
overlay wiring:their first upgrade still needs the release announcement. The
server can reject them,but cannot add new rendering code to their old helper.
