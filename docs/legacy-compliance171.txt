Feature inventory

Original flow:LoginResponse contains nonempty JudgeLoginData/AIS instructions
->FinalizeLoginResponse sets its compliance wait and dispatches JudgeLogin
->UIMenuController.OnJudgeLogin creates the Korean dialog prefab
->the initialized view processes the server-supplied URL/instructions
->close/confirm calls the original ValidateJudgeLogin request
->its response resumes the original finalizer. This is a legacy account/login
feature,not an identified requirement for community gameplay or LAN networking.
Current OfflineInitialUpdate creates local profile/version state and enters
the menu directly;OfflineFrontUpdate owns no original front-service connection.

with empty InitialUrl. It also contains an enabled Vuplex CanvasWebViewDemo
on an active child named "Scripting API Example". These are serialized template
defaults,not proof a live scene creates them. Blocking the entire dialog's
creation route also blocks that child on this route.

Application.OpenURL(System.String),rather than Vuplex. Its existing code is
unchanged. Steam overlay/HTML and file-browser library types are not by

Implementation
client_patch/patcher/legacy_compliance.py supplies four exact-original-byte
patches included by patch_client.PATCHES in both local and community variants:
1. UIMenuController.OnJudgeLogin RVA3d508d0:instance-void return before prologue
   or input access,preventing the known Korean prefab creation route.
2. FrontServerIntegration.ValidateJudgeLogin RVA3e3af60:instance-void return
   before request construction/enqueue,preventing original validation requests.
3. FinalizeLoginResponse RVA3e3f11a:clear only _pendingJudgeLogin byte+108;
   replace the following old pending-wait branch with NOPs. Preserve the
   original stack/nonvolatile registers and subsequent fallthrough.
4. RVA3e3f1f2:unconditional jump to the existing null-JudgeLoginData target
   3e3f298,before compliance event dispatch and pending-flag assignment.
   E9 displacement is0xa1;the sixth byte is NOP.
The last two changes avoid silently hiding the dialog while leaving an old
login response waiting forever. They do not fabricate remote validation success.
If no pending response exists,the original early return remains. The rest of
the original finalizer is unchanged;restored official-service login is not a
supported community-client scenario or a new qualification claim.

Adjacent original judge-pay/timing response bodies only log instruction counts;
they do not create this dialog. They were inspected but not broadened into this
change. Survey,Vuplex library/license/cache/render code,shared APIs,community
transport,gameplay and local diagnostics are unchanged.
