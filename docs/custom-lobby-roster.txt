IMPLEMENTATION BOUNDARY
The invite screen has a native pool, ordinary FriendModel-backed row, and a child
FriendVM renderer. It is possible to keep pool/lifecycle/invite actions while
replacing the directory source and selected presentation calls. Do not put
synthetic profiles into UncappedSteamFriends globally, force its initialized flag
true, or let synthetic models enter original Steam name/status/avatar code.

There are TWO distinct renderer strategies, not interchangeable assumptions:
A. Narrow callers: intercept the row/popup child FriendVM.set_Model calls and
   render FriendVM public properties without binding the child to FriendModel.
   The OUTER row still uses original model binding for InviteToGame and pending
   refresh. This avoids shared FriendVM entry changes. It deliberately makes the
   child presentation-only; IsModelSet/serialized visibility, clearing the popup
   when no invite remains, and disabled child actions need qualification. It is
   a promising bounded experiment, not a proven drop-in normal binding.
B. Preserve full native child model binding, but conditionally replace
   FriendVM.RefreshViewModel for exact owned server models. This covers virtual
   model-change callbacks as well as initial set_Model. An ENTRY patch needs a
   genuine original-prologue trampoline for all non-owned models. Calling the
   same patched original RVA recurses. An exact simple prologue is provided
   below, but no gateway was implemented or tested in this review.

AliasedVersion=true is NOT a third safe option. Original FriendVM.Refresh always
reaches SteamFriends.GetInternal/status calls after its name branch, and later
avatar logic. In its ordinary display-name branch both alias variants call
Steamworks.Friend.get_Name, with one appending an alias suffix.

FRIENDMODEL CONSTRUCTION: WHAT IS SAFE TO ASSUME
FriendModel#3382 is a managed model object, not a Unity GameObject/component:
  _friend10:Steamworks.Friend (one uint64 SteamId value),
  _friendExtension18:FriendExtension, _isImageDirty20 bool,
  _image28:Texture2D, _modelChanged30:Action.
It has NO noarg constructor. The actual ctor3cff510 is
  .ctor(ref Steamworks.Friend friend, bool aliased)
  ABI RCX allocated this, RDX pointer to the 8-byte value, R8B bool, R9 metadata.
Do not pass a boxed Friend object as the ref value. The constructor allocates a
FriendExtension, marks image dirty, writes extension.AliasedVersion, copies the
Friend value, then calls UpdateFriendExtension3cff600 at3cff5bf. This call reads
Steam rich presence (GetAliased, GetRichPresence etc). It is unsafe unmodified
for synthetic non-Steam identities, regardless of aliased=true.
set_Friend3cff3e0 also updates native extension; do not use it for these models.
get_DisplayName3cff420 calls Steam name, get_OnlineStatus3d00580 queries Steam,
EnsureSteamAvatarUpdated3cfff10 can start an async Steam avatar request. Avoid all
three. Observe3d00240/Unobserve3d003e0 manage the modelChanged delegate.

FriendExtension#3380 has trivial noarg ctor6af170 and fields:
  AliasedVersion10 bool, AliasedFriendModel18:FriendModel, IsAliased20 bool,
  PartyStatus24 enum, Region28 enum, PlayerHandle30:named handle,
  FrontHandle38:ServiceHandle, Environment40 string,
  SteamDisplayRichPresence48 string, GameConnectionInfo50,
  BannerId58:IntKey<CosmeticItem>, PortraitId5c:IntKey<CosmeticItem>,
  GameMode60 enum, ExternalRating64 int, League68 enum.
Keep canonical named handles exactly consistent with the lobby identity map.
The underlying Friend uint64 is only an adapter lookup key, not Steam identity
or evidence of Steam friendship. Synthetic models must stay in owned caches,
not _lookupFriends/_sortedFriends or Steam event subscriptions.

Two concrete construction choices, each needing qualification:
  - Native ctor with the exact internal UpdateFriendExtension call wrapped.
    Use a strictly scoped Unity-thread construction record rooted to this exact
    object; populate its newly allocated extension from directory data and skip
    only that Steam update. On all other models call original3cff600. Constructor
    then completes normally; its modelChanged is initially null. Set image dirty
    false/empty image for owned models and never run the avatar method.
  - Checked object_new(FriendModel) plus object_new/ctor(FriendExtension), then
    set the fully evidenced fields with IL2CPP field barriers. This deliberately
    reconstructs the simple owned model constructor while omitting Steam work;
    do not call a nonexistent noarg ctor. It is feasible from the traced body,
    but remains a new adapter constructor, not an existing game-supported API.
Both choices require the rendering route to keep native Steam refresh away from
owned models. Do not recommend raw object allocation by itself as a complete fix.

The same slot is used by the row and both popup child bindings. Preserve native
metadata when forwarding non-owned models through that original slot.
If applying strategy A, do NOT forward owned bindings to the original setter and
then overwrite the name: the setter can synchronously invoke Steam Refresh.

intact and owned Refresh renders the properties above. The native FriendVM entry
RVA3d027b0/raw3d00db0 begins eight whole bytes:
  40 55 56 48 8d 6c 24 e8

executes those exact eight bytes then jumps to module+3d027b8, preserving RCX/RDX,
stack, nonvolatile registers and Windows x64 unwind behavior. A statically
assembled helper stub may avoid runtime executable allocation, but its unwind
and relocation design still needs review. Never simply call module+3d027b0 or
module+3d027b8 as an ordinary C++ function after entry patching.
